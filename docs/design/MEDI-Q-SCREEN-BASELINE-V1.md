## 2. 이미지 사용 기준

참조 이미지는 본 폴더 assets/의 mediq-concept-a.png, mediq-concept-b.png, mediq-concept-c.png다.

- AI 생성 컨셉이며 실제 환자 영상·실제 상태·검증 증적이 아니다.
- 화면 비율, 여백, 색상, 타이포 위계만 참고한다. 임의 인명·생년월일·수치·의료정보·완료 표시는 가져오지 않는다.
- C 원본은 의료진 예시이므로 **환자용으로 내용과 행동을 재구성**한다. 원본을 그대로 복제하지 않는다.
- 기존 사용자 제공 네이비 사각 Q 로고를 유지한다. 생성 이미지의 새 심벌은 채택하지 않는다.
- 생성된 CT/MRI 이미지를 실제 Viewer 또는 오류 대체 이미지로 사용하지 않는다.

## 4. MQ-A 의료진 기본 화면

```text
┌ 76px 탐색 ┬ 로고 / 검사 검색 / 소속 병원·사용자 ───────────────┐
│           ├ 검사 목록 260px ┬ 선택 검사·미리보기 flex ┬ 상세 300px│
│ 교환      │ 검색·필터       │ 검사명·출처·검사일       │ 동의       │
│ Viewer    │ CT / MR 목록    │ 확인된 단계 요약         │ 목적·기간  │
│ QR 연결   │ 현재 선택 강조  │ 승인된 영상 / 잠금 안내  │ 범위·기관  │
│ 전달 기록 │ 독립 스크롤     │ 최소 도구 / B로 열기     │ 다음 행동  │
└───────────┴────────────────┴─────────────────────────┴──────────┘
```

상단 64px. 제목 영역은 최대 72px. 1440×900 이상에서 영상/잠금 영역과 주요 행동이 첫 viewport에 보인다. 목록을 영상 위에 쌓지 않는다. 초기 선택은 첫 조회 항목의 메타데이터만이며 픽셀 자동 요청 금지.

| 요소 | 행동·표시 계약 |
|---|---|
| 검색 | 검사명·종류·검사일·출처 검색. API가 제공하지 않는 환자/요청 검색은 안내하지 않음 |
| 목록 | 검사명·종류·날짜·출처·동의 상태. 썸네일도 인증된 픽셀만; 없으면 CT/MR 표시 |
| 선택 | 단일 Study 컨텍스트. 이전 영상 정리, 지연 응답 폐기. 상세 선택만으로 토큰 발급 금지 |
| 중앙 | 초기 잠금 안내. ‘미리보기’ 명시 동작으로 기존 접근 검증 후 허용 Instance만 표시 |
| 오른쪽 | 동의/목적/기간/허용 범위/수신기관. UID·토큰·실명은 기본 표시하지 않음 |
| 기본 CTA | ‘영상 열람’ → 검증 중 → 허용되면 B, 거부면 A에서 이유·복구 안내 |
| 보조 CTA | ‘요청 상세’; 서버가 확인한 전달 정보가 있을 때만 ‘전달 상태 확인’ |

진행 단계: 동의 확인 → 접근 검증 → 영상 열람. 별도의 전송이 존재할 때만 전송/수신 단계를 표시한다. 연구 목적·다운로드·PACS_IMPORT는 VIEW에서 자동 확장하지 않는다.

## 5. MQ-B 의료진 집중 Viewer

```text
┌ 워크스페이스로 돌아가기 / 검사명 / 최소 조작 도구 ───────────┐
│ Series 144px │ 검정 영상 캔버스 flex       │ 접이식 세션 280px│
│              │ 현재 슬라이스·최소 워터마크 │ 동의·범위·만료   │
├──────────────┴ 슬라이스 이동 / 현재 번호 ┴ 허용 작업 ───────┤
└ 합성 데이터 · 임상 판단용 아님 ─────────────────────────────┘
```

- A와 별도 화면. 일반 탐색 메뉴·검색·통계는 숨긴다. 기본 단일 viewport, 기존 지원이 검증된 경우에만 비교 모드 제공.
- 확대·이동·명암·반전·초기화·Series 선택·슬라이스 이동은 기존 기능을 연결한다. MPR/3D/진단 기능은 새로 약속하지 않는다.
- 다운로드 버튼은 해당 권한과 Instance가 있을 때만 활성화. PACS 반입은 별도 절차로 이동하며 열람 권한을 재사용하지 않는다.
- 돌아가기: A의 검색/필터/선택을 유지, 자동 재발급/다운로드 없음. 영상 캐시 보존은 기존 보안 정책과 유효기간을 넘지 않는다.
- 만료/철회/컨텍스트 변경: 픽셀·썸네일·blob 참조 즉시 정리, cine 정지, 재검증 안내. 늦은 응답으로 복원하지 않음.
- 실제 영상 영역에 실제 DICOM 응답만 표시. 해부학적으로 사실적인 생성 이미지 사용 금지.

## 6. MQ-C 환자 기본 화면

```text
┌ 200px 메뉴 ┬ 로고 / 내 영상 검색 / 내 계정 ─────────────────┐
│ 홈         │ 내 의료영상                                   │
│ 내 영상    ├ 확인할 요청 (있을 때만) ────────────────────────┤
│ 동의 관리  │ 영상 목록·선택 상세 flex    │ 공유 요청 320px  │
│ 활동 이력  │ CT / MRI · 출처·검사일     │ 병원·목적·범위   │
│ 병원 연결  │ 본인 열람 / 병원과 공유    │ 기간·승인·거절   │
└────────────┴───────────────────────────┴───────────────────┘
```

- C의 청록·여백·단순 위계를 채택. ‘오늘의 영상 교류’, 의료진 KPI, PACS 메뉴, 의료진 도구는 환자 화면에 두지 않는다.
- 요청 없음: ‘확인할 요청이 없습니다’ 한 줄. 빈 활동을 가짜 이벤트로 채우지 않는다.
- ‘요청 확인’ → 병원·목적·Study/Series·기간·다운로드 여부 확인 → ‘동의하고 승인’ 또는 ‘거절’. 확인 화면 없이 승인하지 않는다.
- ‘병원과 공유’는 기존 동의 생성 계약 사용. 병원 지정/범위/목적/기간을 검토한 후 제출; 무제한 기본값 금지.
- 동의 관리에서 ‘동의 철회’ → 대상·영향 확인 → 서버 확인 후 철회 표시. 서비스 만료와 환자 철회를 구분.
- QR는 본인 동의 범위 내 기존 흐름만 사용. 사용·만료·철회·확인 장애 시 제거.
- 활동은 본인에게 허용된 영수증/동의 이력만. 관리자 원시 감사로그 노출 금지.
- 본인 Viewer의 실영상 API가 미연결이면 명시한다. 목업 Canvas를 실제 의료영상으로 표현하지 않는다.

## 7. 반응형·키보드

- 1280~1439px: A 목록 220px/상세 260px, 중앙 우선. B 세션 패널 기본 접힘.
- 768~1279px: A 상세는 버튼으로 여는 패널, 목록은 접을 수 있음. C 공유 상세는 메인 아래. 패널은 초점 관리·Escape·복귀 제공.
- 767px 이하: C는 홈/내 영상/동의/활동 하단 메뉴, 요청을 먼저 표시. A는 목록 → 상세 드릴다운. B 단일 영상+하단 도구, 우측 패널은 별도 sheet.
- 200% 확대, 키보드만 사용, 명확한 focus, 색상 외 상태, reduced-motion 지원. 화면 전체 가로 스크롤 금지, 필요한 표만 내부 스크롤.

## 8. 상태·오류·보안 계약

| 상태 | 표현과 동작 |
|---|---|
| 초기/미선택 | 검사 선택 안내; 기본 초록 PASS 없음 |
| 로딩 | 해당 영역 skeleton/문구, 중복 제출 차단; 기한 없는 spinner 금지 |
| 정상 빈 응답 | 빈 상태와 다음 동작; 실패 응답을 0건으로 바꾸지 않음 |
| 동의 없음/철회/만료 | 해당 상태 문구, 안전한 다음 행동, 영상 숨김 |
| 네트워크/TLS/서버 오류 | ‘확인하지 못했습니다’+재시도; 정책 DENY와 구분 |
| 미지원/미연결 | 비활성 또는 숨김+설명; 클릭 가능한 가짜 기능 금지 |

계정 역할·병원·목적·scope는 서버가 최종 검증한다. 접근토큰은 URL/로그/화면에 노출하지 않는다. 실제 환자정보 금지. 운영 상태·법률 적합성을 디자인 배지로 보증하지 않는다.

## 9. 구현 순서·수용 기준

1. 기존 공통 토큰에 A/B/C 테마와 navigation/StudyList/Status/Details/ActionBar 규격 반영.
2. A: 좌우 목록·상세 고정, 중앙 우선, 검색·선택·상태·잠금 완료.
3. B: A와 독립된 Viewer, 단일 컨트롤러 재사용, 진입/복귀 및 만료 정리 검증.
4. C: 환자 행동 중심 재배치, 동의·철회·QR 기존 기능 연결.
5. 목표 해상도 스크린샷, 실제 합성 데이터 정상·음성·지연 응답, 키보드/확대 검증.

| 수용 기준 | 확인 방법 |
|---|---|
| A와 B가 분리됨 | A에서 열람 진입 및 B에서 선택 유지 복귀 |
| 영상 우선 배치 | 1440×900에서 중앙 영상/잠금 및 CTA가 첫 화면 안에 존재 |
| C가 환자 화면임 | 의료진 KPI/PACS/원시 감사 제거, 요청·승인·철회 동선 확인 |
| 실제 데이터와 상태 일치 | API/권한/기간/수신 결과별 UI 매핑 확인 |
| 기능 회귀 없음 | 동의·토큰·scope·Viewer·철회·QR 정상/음성 테스트 |
| 시각 일관성 | A/B/C 참조와 나란히 검토, 로고·타이포·여백·대비 확인 |

관련 FR: 001~005 동의, 006~013 목록·접근, 014~025 정책·토큰, 026~036 Gateway·Viewer, 037~041 본인/권한 범위 이력.

본 기준 확정은 구현 완료가 아니다. 현재 코드의 A/B 통합 화면은 이 기준과 달라 후속 수정 대상이다. 이번 작업은 문서·참조 자산 등록만 수행하며 코드 테스트/배포 판정은 NOT VERIFIED다.
