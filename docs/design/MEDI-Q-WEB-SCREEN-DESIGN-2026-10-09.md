# Medi Q 웹 화면 설계 v0.1

> 시각 배치와 구현 순서는 [화면 설계 기준 v1.0](MEDI-Q-SCREEN-BASELINE-V1.md)으로 대체되었다. 본 문서는 이전 설계 이력으로 보존한다.

작성일: 2026-10-09 · DRAFT / UNASSIGNED · 설계안이며 구현/승인 완료 아님

## 1. 기준과 결정

- 표시 이름은 **Medi Q**, 로고는 [브랜드 기준](MEDI-Q-BRAND-REFERENCE-2026-10-09.md)의 원본 네이비 사각 Q. API·DB·환경변수 이름은 변경하지 않는다.
- 환자 웹 기준: `C:/Users/user/Downloads/환자용 웹화면.png`.
- 의료진 웹 기준: `C:/Users/user/Downloads/의료진 웹화면.png`.
- 추가 앱 자료: `C:/Users/user/Documents/카카오톡 받은 파일/Desktop/앱 목업 개발/`. 앱의 로고·구성 참고이며 문서 속 기능을 새 요구사항으로 자동 승인하지 않는다.
- 시안의 배치·비율·색감 재현을 목표로 한다. 예시 환자명·건수·승인 결과를 그대로 복사하지 않는다.
- 기존 환자 홈은 재구성 1차, 의료진 화면은 공통 스타일 적용 단계다. 이 문서는 다음 상세 재구성 기준이다.

관련 요구사항: FR-001~005 동의, FR-006~013 목록·접근, FR-014~025 정책·토큰, FR-026~036 Gateway·Viewer, FR-037~041 감사. 신규 v3 Mapping·Grant의 완료 판정을 기존 토큰으로 대신하지 않는다.

## 2. 공통 시각 규격

기준 캔버스 1672×941px, 추가 확인 1440×900·1280×800·390×844. 크기는 설계 목표이며 현재 측정값이 아니다.

| 요소 | 설계 목표 |
|---|---|
| 색 | 주요 행동 #2563EB, 텍스트 #0F172A, 배경 #F3F8FF, 카드 #FFFFFF, 선 #E2E8F0, 위험 #991B1B |
| 로고 | 원본 픽셀·종횡비 유지. 재생성/색상 변경 금지 |
| 글꼴 | 기존 한국어 시스템 글꼴 사용, 외부 CDN 없이 실행 |
| 글자 | 페이지 제목 26~28px, 카드 제목 17~18px, 본문 14px, 보조 12~13px |
| 간격 | 화면 여백 24px, 패널 간격 14~16px, 카드 내부 16~20px |
| 형태 | 카드 radius 12px, 버튼 8px, 최소 조작 영역 44px |
| 상태 | 텍스트+아이콘+색상. ALLOW·DENY·만료·철회·미확인을 구분 |
| Viewer | 검은색/짙은 네이비 뷰포트, 승인된 픽셀만 표시 |

기존 `public/ui/tokens.css`를 유지한다. 화면별 CSS에서 새로운 병렬 토큰 체계를 만들지 않는다. frontend-design의 시안 우선 원칙을 적용하며 임의의 새로운 랜딩페이지 스타일로 바꾸지 않는다.

## 3. 환자 웹 구조

```text
┌ 로고 ─────── 영상 검색 ─────────── 합성 배지 / 알림 / 사용자 ┐
│ 좌측 메뉴 │ 인사·설명                              공유 시작 │
│ 216px     │ 영상 수 / 동의 상태 / 공유 이력 / 병원 연결       │
│           ├ 동의 확인·승인 요청 ───────────┬ 보호 안내 ─────┤
│ 빠른 작업 │ 내 의료영상 2카드 │ 미리보기    │ 전달 상태      │
│ 모바일    │                  │             │ 최근 활동      │
│           ├ 이용 도움말 ──────────────────┼ FAQ ──────────┤
└───────────┴ 비운영·합성 데이터 안내 ─────────────────────────┘
```

현재 역할 전환 개발용 바는 본 서비스 헤더와 분리한다. 제거하더라도 개발용 접근 경로를 숨겨서 없애지 않고 별도 시연 도구로 옮긴다. 실제 인증 역할 전환으로 오인시키지 않는다.

| 화면 ID | 구성 및 행동 | 데이터/경계 |
|---|---|---|
| MQ-P-01 홈 | 시안 패널 배치, 영상 선택·동의 검토 진입 | 실제 목록/본인 동의. 의료진 승인 inbox 미연결이면 ‘동의 관리’로 표시 |
| MQ-P-02 영상 목록 | 검사명·날짜·병원·modality 검색, 카드/상세 | 목록 전체 검색으로 확장; 현재 홈 검색은 표시된 2개만 대상임을 유지 |
| MQ-P-03 검사 상세 | Study/Series 범위, 검사일·출처, 열람/공유 버튼 | 과도한 UID 출력 금지. 선택 범위가 동의 폼에 그대로 전달 |
| MQ-P-04 공유 동의 | 제공·수신 병원, 목적, 기간, 권한, 범위 → 검토 → 제출 | 기존 createPatientConsent 계약 유지; 서버 확인 전 성공 표시 금지 |
| MQ-P-05 QR | QR·절대 만료시각·사용 상태·철회 진입 | 서버 확인 후 노출, 사용/철회/만료/조회 장애 시 숨김 |
| MQ-P-06 동의·활동 | 본인 생성·철회 이력, 상태별 필터 | raw 관리자 감사로그 미노출. 상세 열람 영수증 미연결 구분 |
| MQ-P-07 도움말 | FAQ·오류 복구·모바일 안내 | AI 응답/의료상담 기능을 가장하지 않음 |

### 미리보기 계약

- 카드 선택 시 검사 제목·범위를 보여주고 명시적인 열람 동작으로 본인 접근 검증을 수행한다.
- 현재 환자 열람 Canvas는 합성 화면이며 실제 DICOM 픽셀 연결 완료가 아니다. 해당 경로를 확인하기 전 인라인 패널에 ‘실제 영상’이라고 표시하지 않는다.
- 데이터 없음, 권한 거부, 로딩, 네트워크 장애를 각기 다르게 표현한다. 정적 CT 사진을 오류 대체물로 사용하지 않는다.
- 전송 단계는 실제 서버 이벤트가 있으면 시각·결과를 표시하고 없으면 ‘확인되지 않음’. 동의 ACTIVE는 전송 완료가 아니다.

## 4. 의료진 웹 구조

```text
┌ 로고 ───────── 환자·검사·요청 검색 ───────── 병원 / 사용자 ┐
│ 좌측 메뉴 │ 의료영상 교환 대시보드       │ 요청 상세       │
│ 208px     │ 진행 / 동의 대기 / 완료 / 확인│ 요약·보안·이력   │
│           ├ 교환 요청 목록 ─────────────┤ 환자 연결·검사   │
│ 빠른 작업 │ 선택 요청 / 기관 / 목적     │ 동의·접근 권한   │
│ QR 연결   │ 동의→권한→전달→수신확인      │ 목적지 확인      │
│           ├ 영상 미리보기 │ 허용 작업   │ 다음 작업        │
│ 상태      │              │ VIEW 등     │ 최근 이력        │
└───────────┴ 이용 안내 ──────────────────┴─────────────────┘
```

우측 상세 폭 목표 340~380px. 가운데 영역은 나머지 폭을 사용한다. 1280px 이하에서는 상세를 목록 아래로 이동해 표·Viewer 폭을 확보한다.

| 화면 ID | 구성 및 행동 | 데이터/경계 |
|---|---|---|
| MQ-H-01 교환 목록 | 요청·검사·기관·작업·상태 열, 행 선택 | inbox/집계 계약이 없으면 현재 영상·동의 목록으로 명시; 가짜 8/3/12/2 금지 |
| MQ-H-02 요청 상세 | 환자 연결, 검사, 동의, 권한, 다음 동작 | 선택된 요청과 동일한 컨텍스트만 표시; 늦은 응답 폐기 |
| MQ-H-03 Viewer | Series 썸네일·단면·슬라이더·조작·만료 | 기존 DPoP/토큰·lazy load 유지, 요청 결과와 이미지 디코딩 실패 구분 |
| MQ-H-04 QR 접수 | 스캔/허용된 수동 입력, 처리 결과 | QR 소비와 영상 전송 완료는 다른 상태 |
| MQ-H-05 반입 | 허용된 요청의 목적지·범위·결과 확인 | VIEW/DOWNLOAD/PACS_IMPORT 별도 권한, 로컬 보관을 PACS 등록이라고 표시하지 않음 |
| MQ-H-06 이력 | 해당 사용자에게 허용된 요청 이력 | 의료진≠보안 관리자. 원시 감사 API 탭은 역할 제한 |

Mapping VALID, Grant VALID, 목적지 검증 완료는 별도 서버 증적 없으면 ‘미확인’이다. 현재 단기 접근토큰 발급 성공으로 세 상태를 일괄 초록색 처리하지 않는다.

## 5. 공통 상태와 입력 계약

| 상태 | 사용자 표현 | 동작 |
|---|---|---|
| 로딩 | ‘확인 중’ | 중복 제출 차단; 기존 값을 최신 값처럼 표시하지 않음 |
| 빈 목록 | ‘조회된 영상이 없습니다’ | 정상 빈 응답에만 적용 |
| 네트워크 오류 | ‘정보를 확인하지 못했습니다’ | 제한시간 후 재시도 제공, 접근 거부와 구분 |
| 권한 거부 | ‘선택한 영상에 접근할 수 없습니다’ | 내부 경로·토큰·stack trace 미출력 |
| 철회·만료 | 명확한 상태와 재동의 안내 | 픽셀·QR·메모리 URL 정리, 늦은 응답 복원 차단 |
| 미지원 | ‘준비 중 / 미연동’ | 클릭 가능한 가짜 기능 금지, 필요한 설명 제공 |

검색·탭·모달은 키보드로 사용 가능해야 한다. 모달 종료 시 초점 복귀, 확대 200%, reduced-motion, 상태 변화의 과도한 aria-live 알림을 점검한다. 썸네일·QR·사용자 입력은 localStorage 또는 일반 Service Worker 캐시에 넣지 않는다.

## 6. 구현 순서 및 수용 기준

1. **환자 shell 정렬**: 중복 상단 바 정리, 시안 크기의 전체 화면 비교, 주요 7패널 위치 검증.
2. **환자 카드/상세 연결**: 전체 목록 검색, 실제 접근 계약 기반 미리보기, 빈/오류/철회 상태.
3. **의료진 3열 재구성**: 목록과 오른쪽 상세의 단일 선택 컨텍스트, 작업별 권한.
4. **동일 디자인의 모바일 정렬**: 기존 4단계 공유를 보존하고 사용자 제공 앱 자료의 위계를 참조.
5. **회귀·증적**: 정상·음성·만료·철회, 화면 비교, 배포 구성 검증 후 별도 배포.

시각 기준: 기준 폭에서 패널 순서·상대 크기·행 정렬·색·타이포를 원본과 나란히 비교한다. 로고와 합성 데이터 차이는 허용된 차이로 기록한다. 인물 일러스트와 실제 픽셀 자산이 빠졌으면 ‘완전 동일’이라고 보고하지 않는다.

기능 기준: 모든 활성 버튼의 목적지가 존재하고 기존 동의·범위가 보존되며, 상태 변경은 서버 응답으로만 확정한다. UI 성공과 종단 보안 성공을 별도 기록한다.

## 7. 불확실성과 이번 산출물

- 확인된 요구: Medi Q 브랜드, 제공 시안 중심의 재현, 기존 보안 기능 유지.
- 설계 가정: 기존 정적 HTML/JS를 유지하고 환자 웹부터 진행. 새 프레임워크 도입 없음.
- 남은 불확실성: 수신 요청 inbox·집계, 안전한 본인 열람 영수증, 환자 실제 픽셀 미리보기의 최종 계약. 구현 전에 현행 서버 코드 재검토 필요.
- 이번 변경: 이 설계서와 문서 인덱스만 작성. 기능 테스트/브라우저 검증은 실행하지 않았으며 모두 NOT VERIFIED. 기존 테스트 결과를 신규 설계의 검증으로 승계하지 않는다.
- CAPSTONE MVP / TECHNICAL TEST ENVIRONMENT ONLY. 법률 적합성·ISMS-P·병원 운영 승인 또는 전체 MVP/v3 완료 주장이 아니다.
