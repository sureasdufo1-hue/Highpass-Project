## 작업 목적과 완료 범위

화면 기준 v1에 따라 A 의료진 기본, B 집중 Viewer, C 환자 기본의 **로컬 UI 재구성**을 수행했다. 기존 화면 위에 카드만 추가하는 방식에서 벗어나 역할별 정보 위계를 재배치했다. frontend-design 스킬의 시안 우선·시각 검토 절차를 적용했다. 서버 기능·배포 완료 판정과 분리한다.

## 작업 단위

1. **A:** 표를 검사 선택 목록으로 교체. 좌측 좁은 탐색, 검사 목록, 중앙 보호된 영상, 우측 동의/기관/권한 정보. 큰 통계 카드 제거. 검사 선택은 픽셀을 자동 요청하지 않는다.
2. **B:** 별도 다크 집중 화면과 돌아가기. 기존 Series·Instance·슬라이스·조작·권한별 다운로드 재사용. A/B가 단일 Viewer DOM을 이동해 사용하므로 별도 픽셀 복사/캐시가 없다.
3. **C:** Quiet Teal 적용, 간결한 상태 요약, 내 영상 목록, 동의 관리, 공유 안내. 중복 미리보기/장식용 도움말 제거. 기존 동의·철회·QR·PHR 경로 보존.
4. **품질 검토:** 화면 왕복, 검색, 선택 상태, 동의 폼 진입, 모바일 너비·하단 메뉴·큰 글자·전체 Node 회귀. 작은 화면의 헤더 줄바꿈과 Viewer 부가 영역을 수정했다.

관련 요구사항: FR-001~005, FR-006~013, FR-014~025, FR-032~036. API/DB 계약 변경 없음. 원시 관리자 감사 접근권한 추가 없음.

## 보안과 남은 한계

- 실제 환자정보·생성 CT 사진으로 결과를 꾸미지 않았다. A/B는 기존 인증된 픽셀 응답을 사용한다.
- C 카드의 그림은 modality 표시다. 본인 실영상 API 미연결을 생성 이미지로 대체하지 않았다. 기존 환자 미리보기의 합성 화면 한계가 남아 있다.
- 생성 시안의 수신 완료·이름·수치는 옮기지 않았다. Mapping/Grant/수신 영수증 미연결 상태 유지.
- 768~1199px의 상세는 별도 drawer 대신 하단으로 배치하는 구현 선택을 했다. 기능 접근을 유지하면서 새 modal 컨트롤러를 추가하지 않기 위한 차이다.
- 네이티브 앱·생체인증·PACS 신규 기능 구현은 이번 디자인 범위가 아니다.
- 컨셉 이미지와 픽셀 단위 동일함을 주장하지 않는다. 실제 합성 영상과 미지원 데이터로 인한 차이를 명시한다.
- 기존 사용자 변경을 보존했다. 커밋·푸시·VM 배포는 하지 않았다. 전체 MVP 완료/운영 승인 주장이 아니다.
